## Retrieval (20 answerable questions per configuration, no retrieval errors)

| Configuration | HitRate@5 | Recall@5 | MRR | No keyword match (answerable / unanswerable) | Search latency median / p95 |
|---|---|---|---|---|---|
| Vector only (production mode) | 1.00 | 0.975 | 0.917 | — | 9.5 / 31 ms |
| **Hybrid: keyword AND, `simple` (production)** | 1.00 | 0.975 | 0.917 | **18 / 20**, 6 / 6 | 7 / 13 ms |
| Hybrid: keyword OR, `simple` (experiment) | 1.00 | **1.000** | **1.000** | 0 / 20, 0 / 6 | 7 / 11 ms |
| Hybrid: keyword AND, `english` (experiment) | 1.00 | 0.975 | 0.950 | 15 / 20, 6 / 6 | 7 / 11 ms |
| Hybrid: keyword OR, `english` (experiment) | 1.00 | **1.000** | 0.975 | 0 / 20, 1 / 6 | 6 / 7 ms |

- **Chance baseline:** a random ranking of 10 chunks would reach HitRate@5 = 0.817 on this dataset (0.778
  for a one-document question, 0.976 for a two-document one). HitRate@5 is saturated, and every
  configuration scores 1.00. **Only MRR and Recall@5 separate the configurations, and only through 4 of
  the 20 questions.**
- **Production hybrid equals vector-only on every question.** The all-words keyword query matched no
  chunk for 18 of the 20 answerable questions, so RRF ranked by vectors alone. The two questions that did
  match (q04 "What is NorthCare Plus?", q09 "Do Northstar gift cards expire?") were already at rank 1 with
  vectors. On this corpus, production hybrid retrieval adds nothing over vector search for natural
  questions. That is the M6 limitation, now measured.
- **Where they differ:**
  - **q06, "What is an RMA number and where do I write it?":** vector ranks the returns policy 3rd.
    Even this exact-term question gets no keyword match under AND, because every word, "what", "is", and
    "an" included, must be in one chunk. With OR it ranks 1st, with `english` AND 1st, and with
    `english` OR 2nd.
  - **q08 and q20 (paraphrases):** vector ranks the support FAQ 2nd; with either OR variant it ranks 1st.
  - **q15, "If I spill water on my Trailblazer 14…":** vector, AND, and `english` AND leave the product
    guide out of the top 5 (recall 0.5); with either OR variant both documents are retrieved.
- **The cost of OR:** with `simple` OR, stop-words match nearly everything. Every unanswerable question
  found keyword matches (10 chunks for "Who won the 1998 football World Cup?"). On a 10-chunk corpus that
  is harmless; on a large one it is noise competing with the vector list. `english` OR drops stop-words
  and stems, so it matched fewer chunks (no keyword match for the World Cup question) for nearly the same
  gain (MRR 0.975).

**Decision: none yet.** The production default stays `simple` AND (ADR 0009). The evidence for a change is
4 questions on 10 chunks. `english` OR is the most promising candidate. Before any change, it should be
measured on a larger corpus with distractor documents (for example, the demo files alongside unrelated
PDFs), because that is where OR's noise would show. The owner decides.

- **Every decided question was decided correctly** in both modes. All 20 answerable questions got an
  answer with a valid citation in hybrid mode, and every unanswerable question that reached the model was
  declined, including the near miss u02 (battery capacity in watt-hours, where the corpus only gives
  battery life). No answer was withheld for lack of citations (`no_valid_citation`: 0).
- **The two modes cannot be ranked from this run.** Production hybrid produced exactly the same top-5
  ranking as vector-only for every question, so both modes sent the same excerpts. Differences between
  their answers are Gemini's own variation. They were also measured on different question sets, because
  provider errors removed 3 vector answers and 1 hybrid answer.
- **Citation imperfections (source level):**
  - **q17, "What about express?" (follow-up):** both modes added a true but unasked fact (fuel
    canisters are never shipped by express) cited to the product guide, so precision is 0.5.
  - **q15 (water damage):** both answered correctly from the warranty policy alone. The product guide
    wasn't retrieved (see above), so citation recall is 0.5. The retrieval miss carries through to the
    citations.
- **Human review of all 37 answers (by Claude, not the owner):** no answer contradicts the documents.
  Some leave details out:
  - q02 (vector) says laptops can be returned "with or without an intact factory seal" but omits the
    10% restocking fee for opened ones;
  - q09 (hybrid) omits that gift cards can't be exchanged for cash;
  - q16 (vector) omits the 10-business-day repair time;
  - q19 (both) omits the shipping-charge exception;
  - q15 (both) omits the splash resistance.

  These are omissions, not invented facts. Source-level citation metrics can't see them, and nothing
  here checks claim by claim.
- **Latency is Gemini's:** search takes milliseconds and the query embedding about 0.8 s (median; p95
  3.1 s); generation dominates. The latency rows cover successful answers only. This run stored no
  timing for its 4 failed attempts, so failed-attempt latency is not measured. **Log-derived estimates,
  not measured evaluation results:** from the worker log's timestamps, the time from each question's
  previous Gemini call to the failure was:

  | Question | Mode | Error | Estimated time to failure |
  |---|---|---|---|
  | q05 | vector | 503 | ≈ 19.7 s |
  | q08 | vector | 504 | ≈ 90.3 s |
  | q10 | vector | 504 | ≈ 89.9 s |
  | u03 | hybrid | 503 | ≈ 1.8 s |

  The two timeouts ran the full 90 s request timeout, longer than the slowest successful vector answer
  (34.2 s), so the p95 above understates what a user waiting through a failure would see. Runs since the
  M9 review fix record failed-attempt latency separately. The run coincided with a high-demand period (503s and 504s). Median 15 s
  per answer is slow for chat, and this run doesn't show whether that is typical.

## Abstention without a threshold

The nearest-chunk cosine distances overlap: answerable questions 0.193–0.387 (median 0.301), unanswerable
0.317–0.527 (median 0.386). No distance threshold separates them. A threshold low enough to catch most
unanswerable questions would also reject answerable ones (8 of the 20 answerable questions are above 0.317, the lowest
unanswerable distance). The
model's own judgement, enforced by the citation check, did the separating in this run (11 of 11 correct
abstentions, 37 of 37 correct answers). That is a small sample, and it says nothing about adversarial or
subtler questions.

## What this run does not show

- Retrieval quality on a realistic corpus: 10 chunks make HitRate@5 meaningless, and most of the signal
  sits in 4 questions.
- Statistical confidence: one run, 26 questions, no repeated answers. Gemini output varies between runs.
- Claim-level faithfulness: citation precision and recall measure whether the cited documents are the
  expected ones (source-level relevance). They don't check that each statement is entailed by its
  citation. There is no LLM judge.
- Production behaviour under load, other languages, scanned PDFs, or long documents.

## Reproduce

1. Sign in, upload the five files in `sample_data/demo_store/` unchanged, and wait until each is ready.
   The evaluation page shows the corpus status.
2. On **Evaluation**, choose what to measure. The page shows the Gemini requests it will reserve. Start
   the run and watch it progress.
3. Open the run to see these tables and every question's retrieved documents, answer, citations, and
   decision. Retrieval metrics are deterministic for a fixed corpus and query embeddings; answers vary
   between runs.
